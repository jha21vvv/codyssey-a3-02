## 1. MOG2 그림자 제거 및 모폴로지 열림·닫힘 파이프라인 (`src/background.py`)
- **선정 이유**: 고전적 영상 처리에서 배경 차분 결과를 그대로 쓰면 그림자와 점 노이즈 때문에 윤곽선이 수십 개로 쪼개집니다. `threshold(200)` + `MORPH_OPEN` + `MORPH_CLOSE` 3단 콤보는 거의 모든 OpenCV 전처리 파이프라인의 표준 패턴입니다.

```python
# [1차-단어분해]: raw_mask(반환 변수) = self._mog2(MOG2 객체).apply(전경 마스크 계산 메서드)(frame(현재 BGR 이미지), learningRate=self.learning_rate(배경 적응 속도 파라미터))
# [2차-예시/비유]: 예를 들어 learning_rate=0.005로 주면, MOG2가 방금 찍힌 CCTV 사진과 평소 배경 기억을 비교해 움직인 곳은 255(흰색), 그림자는 127(회색), 배경은 0(검정)으로 칠한 밑그림을 그려줍니다.
raw_mask = self._mog2.apply(frame, learningRate=self.learning_rate)

# [1차-단어분해]: _(사용 안 하는 임계값 반환 무시), binary_mask(결과 이진 마스크) = cv2.threshold(임계값 처리 함수)(raw_mask(입력), 200(기준값), 255(최댓값), cv2.THRESH_BINARY(기준 초과만 255로 변환하는 플래그))
# [2차-예시/비유]: 그림자(127)는 200보다 작으므로 0(검정)으로 지워버리고, 진짜 사람 몸통(255)만 200보다 크므로 255(흰색)로 살려두는 그림자 제거 필터입니다.
_, binary_mask = cv2.threshold(raw_mask, 200, 255, cv2.THRESH_BINARY)

# [1차-단어분해]: opened(열림 연산 결과) = cv2.morphologyEx(형태학 변환 함수)(binary_mask(이진 마스크), cv2.MORPH_OPEN(침식 후 팽창 연산 코드), self.kernel(5x5 타원 구조 요소))
# [2차-예시/비유]: 화면에 흩뿌려진 1~3픽셀짜리 소금 노이즈(흰 먼지)를 5x5 빗자루로 싹 쓸어내어 없애는 1차 청소 단계입니다.
opened = cv2.morphologyEx(binary_mask, cv2.MORPH_OPEN, self.kernel)

# [1차-단어분해]: cleaned(닫힘 연산 결과) = cv2.morphologyEx(형태학 변환 함수)(opened(열림 완료 마스크), cv2.MORPH_CLOSE(팽창 후 침식 연산 코드), self.kernel(5x5 타원 구조 요소))
# [2차-예시/비유]: 옷 색깔이 배경과 비슷해서 사람 배 부분에 뚫린 작은 검은 구멍들을 퍼티로 메워, 쪼개지지 않은 단단한 1개의 사람 실루엣으로 합치는 2차 마감 단계입니다.
cleaned = cv2.morphologyEx(opened, cv2.MORPH_CLOSE, self.kernel)
```

## 2. 윤곽선 추출·면적 필터링·결정론적 정렬 (`src/detector.py`)
- **선정 이유**: `findContours` 반환 순서는 OpenCV 버전이나 미세 픽셀 변화에 따라 달라질 수 있습니다. 면적 필터링으로 노이즈와 조명 붕괴를 거르고, 좌표 기준 정렬로 재현성을 확보하는 패턴은 실무 테스트 안정성의 핵심입니다.

```python
# [1차-단어분해]: contours(윤곽선 좌표 목록), _(계층 구조 무시) = cv2.findContours(윤곽선 추출 함수)(fg_mask(2D 이진 마스크), cv2.RETR_EXTERNAL(최외곽선만 추출 플래그), cv2.CHAIN_APPROX_SIMPLE(직선 중간점 생략 압축 플래그))
# [2차-예시/비유]: 흰 실루엣 덩어리들의 바깥 테두리만 따라 그리되, 직선 구간은 꼭짓점만 남겨 메모리를 아끼는 도면 작성기입니다.
contours, _ = cv2.findContours(fg_mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)

# [1차-단어분해]: for(반복문) contour(단일 윤곽선 점 배열) in(순회) contours(전체 윤곽선 목록):
# [2차-예시/비유]: 화면에서 찾아낸 흰 덩어리들을 하나씩 저울 위로 올려 검사합니다.
for contour in contours:
    # [1차-단어분해]: area(넓이 변수) = float(실수 형변환)(cv2.contourArea(윤곽선 내부 면적 계산 함수)(contour(현재 윤곽선)))
    # [2차-예시/비유]: 예를 들어 20x30 크기 사람이라면 약 600.0 픽셀²처럼 덩어리의 넓이를 계산합니다.
    area = float(cv2.contourArea(contour))
    # [1차-단어분해]: if(조건문) area < self.min_area(최소 면적 미만) or(또는) area > self.max_area(최대 면적 초과): continue(다음 윤곽선으로 건너뜀)
    # [2차-예시/비유]: 500픽셀보다 작으면 날파리·노이즈, 100,000픽셀보다 크면 조명 급변으로 화면 전체가 번진 것이므로 과감히 걸러냅니다.
    if area < self.min_area or area > self.max_area:
        continue
    # [1차-단어분해]: x, y, w, h(좌상단 좌표와 너비·높이 언패킹) = cv2.boundingRect(최소 외접 직사각형 계산 함수)(contour(현재 윤곽선))
    # [2차-예시/비유]: 사람 실루엣이 쏙 들어가는 가장 작은 택배 상자의 위치(x=120, y=80)와 크기(w=40, h=90)를 구합니다.
    x, y, w, h = cv2.boundingRect(contour)
    # [1차-단어분해]: cx(중심 X), cy(중심 Y) = int(정수 변환)(x + w / 2), int(y + h / 2)
    # [2차-예시/비유]: x=120, w=40이면 가로 정중앙 cx=140처럼, 상자 한가운데에 배꼽 핀을 꽂습니다.
    cx, cy = int(x + w / 2), int(y + h / 2)

# [1차-단어분해]: detections(리스트).sort(제자리 정렬 메서드)(key=lambda d(각 Detection 객체): (d.centroid[0](중심 X), d.centroid[1](중심 Y), -d.area(면적 내림차순)))
# [2차-예시/비유]: 매번 실행할 때마다 객체 순서가 흔들리지 않도록 왼쪽→오른쪽, 위→아래, 큰 덩어리 순으로 일관되게 줄을 세웁니다.
detections.sort(key=lambda d: (d.centroid[0], d.centroid[1], -d.area))
```

## 3. 유클리드 거리 행렬 및 결정론적 타이 브레이킹 매칭 (`src/tracker.py`)
- **선정 이유**: 다중 객체 추적(MOT)의 가장 기본이 되는 데이터 연관(Data Association) 알고리즘입니다. `math.hypot`과 3-튜플 `(dist, obj_id, det_idx)` 정렬을 통한 동률(Tie-breaking) 방어는 알고리즘 면접에서도 자주 묻는 패턴입니다.

```python
# [1차-단어분해]: object_ids(정렬된 기존 ID 리스트) = sorted(오름차순 정렬 함수)(self.objects(추적 딕셔너리).keys(ID 키 뷰))
# [2차-예시/비유]: 현재 매장에 있는 손님 번호표 [1, 2, 3]을 작은 번호부터 가지런히 꺼냅니다.
object_ids = sorted(self.objects.keys())

# [1차-단어분해]: pairs(후보 쌍 리스트): List[Tuple[float, int, int]](거리, 기존ID, 감지인덱스 튜플 타입) = [](빈 리스트 초기화)
# [2차-예시/비유]: "누가 누구와 몇 픽셀 떨어졌는지" 적어둘 빈 거리 대진표를 준비합니다.
pairs: List[Tuple[float, int, int]] = []

# [1차-단어분해]: for obj_id in object_ids: ref_pt(기준점) = self._reference_point(현재 위치 또는 속도 예측 위치 계산)(self.objects[obj_id])
# [2차-예시/비유]: 각 손님의 비교 기준점(예: (100, 200))을 꺼냅니다.
for obj_id in object_ids:
    ref_pt = self._reference_point(self.objects[obj_id])
    # [1차-단어분해]: for det_idx(감지 번호), det(Detection 객체) in enumerate(인덱스+값 동시 순회)(detections):
    # [2차-예시/비유]: 이번 프레임에서 새로 발견된 모든 위치들과 하나씩 거리를 재봅니다.
    for det_idx, det in enumerate(detections):
        # [1차-단어분해]: dist(직선 거리) = self._euclidean_distance(math.hypot 호출)(ref_pt, (float(det.centroid[0]), float(det.centroid[1])))
        # [2차-예시/비유]: 가로 3px, 세로 4px 차이면 직선 거리 5.0px로 피타고라스 줄자로 잽니다.
        dist = self._euclidean_distance(ref_pt, (float(det.centroid[0]), float(det.centroid[1])))
        # [1차-단어분해]: pairs.append(리스트 추가)((dist(1순위: 거리), obj_id(2순위: 기존 ID), det_idx(3순위: 감지 인덱스)))
        # [2차-예시/비유]: 두 손님이 똑같이 10.0px로 비겨도 ID 1번이 ID 2번보다 항상 먼저 선택되도록 동률 규칙을 못 박아둡니다.
        pairs.append((dist, obj_id, det_idx))

# [1차-단어분해]: pairs.sort(오름차순 정렬)(key=lambda item: (item[0], item[1], item[2])(거리→ID→인덱스 순))
# [2차-예시/비유]: 대진표를 가장 가까운 커플 후보 순서대로 줄 세웁니다.
pairs.sort(key=lambda item: (item[0], item[1], item[2]))
```

## 4. 탐욕 1:1 매칭 및 최대 거리 임계값 조기 종료 (`src/tracker.py`)
- **선정 이유**: 정렬된 후보 쌍에서 `dist > max_distance`일 때 `break`로 조기 종료하고, `used_object_ids` / `used_det_indices` 집합으로 중복 매칭을 원천 차단하는 깔끔한 $O(1)$ 조회 패턴입니다.

```python
# [1차-단어분해]: used_object_ids(매칭 완료 기존 ID 집합), used_det_indices(매칭 완료 감지 인덱스 집합) = set(), set()
# [2차-예시/비유]: 이미 짝을 찾은 손님과 위치에 "매칭 끝!" 도장을 찍어두는 중복 방지 장부 2개입니다.
used_object_ids = set()
used_det_indices = set()

# [1차-단어분해]: for dist, obj_id, det_idx in pairs(정렬된 후보 쌍 순회):
# [2차-예시/비유]: 제일 가까운 커플부터 차례로 검토합니다.
for dist, obj_id, det_idx in pairs:
    # [1차-단어분해]: if dist > self.max_distance(허용 최대 보폭 초과): break(정렬 상태이므로 나머지 전부 초과 → 즉시 반복 종료)
    # [2차-예시/비유]: 거리가 80px을 넘으면 같은 사람이 한 걸음에 순간이동한 게 아니므로 여기서 바로 매칭을 마감합니다.
    if dist > self.max_distance:
        break
    # [1차-단어분해]: if obj_id in used_object_ids(O(1) 집합 조회) or det_idx in used_det_indices: continue(이미 짝이 있으면 건너뜀)
    # [2차-예시/비유]: 둘 중 하나라도 이미 다른 사람과 짝지어졌다면 겹치지 않게 패스합니다.
    if obj_id in used_object_ids or det_idx in used_det_indices:
        continue
    # [1차-단어분해]: obj.velocity = (float(det.centroid[0] - obj.centroid[0]), float(det.centroid[1] - obj.centroid[1]))(직전 대비 이동 벡터 갱신)
    # [2차-예시/비유]: (100, 50)에서 (108, 50)으로 갔다면 속도 (+8.0, 0.0)을 속도계에 기록합니다.
    obj = self.objects[obj_id]
    obj.velocity = (float(det.centroid[0] - obj.centroid[0]), float(det.centroid[1] - obj.centroid[1]))
    # [1차-단어분해]: obj.trajectory.append(det.centroid)(maxlen=50 deque 끝에 새 중심점 추가; 50개 초과 시 맨 앞 자동 삭제)
    # [2차-예시/비유]: 발자국 컨베이어 벨트에 새 발자국을 올리면 51번째 오래된 발자국은 자동으로 떨어져 메모리가 늘지 않습니다.
    obj.trajectory.append(det.centroid)
```

## 5. 등속 예측 규칙 (`_reference_point`, `src/tracker.py`)
- **선정 이유**: "단순 위치 비교의 한계를 규칙으로 개선해본 시도"를 단 5줄로 구현한 코드입니다. 직선 교차에서는 ID Switch를 크게 줄이지만, 교차 직후 방향을 틀면 오히려 오매칭을 유발하는 고전 규칙 기반의 한계를 직접 증명합니다.

```python
# [1차-단어분해]: def _reference_point(내부 헬퍼 메서드)(self, obj: TrackedObject) -> Tuple[float, float](실수 좌표 튜플 반환):
# [2차-예시/비유]: "다음 프레임에 이 사람이 어디 있을지" 기준점을 계산하는 예측기입니다.
def _reference_point(self, obj: TrackedObject) -> Tuple[float, float]:
    # [1차-단어분해]: if self.use_velocity_prediction(옵션 활성화 여부) and len(obj.trajectory) >= 2(최소 2프레임 이상 이동 기록 존재):
    # [2차-예시/비유]: 관성 예측 스위치가 켜져 있고, 최소 두 걸음 이상 걸어 속도 방향을 알 수 있을 때만 예측합니다.
    if self.use_velocity_prediction and len(obj.trajectory) >= 2:
        # [1차-단어분해]: return (obj.centroid[0] + obj.velocity[0](현재 X + 직전 X속도), obj.centroid[1] + obj.velocity[1](현재 Y + 직전 Y속도))
        # [2차-예시/비유]: 방금 x=45에서 오른쪽으로 +15px 뛰었다면, 다음 프레임엔 x=60쯤 있을 거라고 미리 앞질러 짚어줍니다.
        return (obj.centroid[0] + obj.velocity[0], obj.centroid[1] + obj.velocity[1])
    # [1차-단어분해]: return (float(obj.centroid[0]), float(obj.centroid[1]))(기본 모드: 현재 중심점 그대로 반환)
    # [2차-예시/비유]: 기본 모드이거나 방금 처음 등장한 손님이면 지금 서 있는 자리 그대로를 기준으로 삼습니다.
    return (float(obj.centroid[0]), float(obj.centroid[1]))
```

## 6. Lowe's Ratio Test 기반 특징점 매칭 (`src/feature_matcher.py`)
- **선정 이유**: ORB/SIFT 매칭에서 단순 1등 매칭만 쓰면 전혀 다른 배경에도 오매칭이 쏟아집니다. `knnMatch(k=2)`로 1등과 2등 거리를 비교하는 Lowe's Ratio Test는 특징점 기반 재인식(Re-ID) 및 파노라마 스티칭의 필수 정석입니다.

```python
# [1차-단어분해]: knn_matches(쌍 목록) = self._matcher(BFMatcher 객체).knnMatch(최근접 k개 매칭 메서드)(self._target_des(타겟 기술자), frame_des(프레임 기술자), k=2(1등과 2등 추출))
# [2차-예시/비유]: 수배 사진의 지문 1개마다 CCTV 화면에서 가장 닮은 후보 1등(m)과 2등(n)을 두 명씩 불러 세웁니다.
knn_matches = self._matcher.knnMatch(self._target_des, frame_des, k=2)

# [1차-단어분해]: good_count(유효 매칭 누적 카운터) = 0
# [2차-예시/비유]: 진짜 일치하는 지문 개수를 셀 카운터를 0으로 맞춥니다.
good_count = 0

# [1차-단어분해]: for pair(후보 쌍 튜플) in knn_matches:
# [2차-예시/비유]: 불러 세운 후보 쌍을 하나씩 심사합니다.
for pair in knn_matches:
    # [1차-단어분해]: if len(pair) == 2(예외적으로 1개만 반환되는 경계 상황 방어):
    # [2차-예시/비유]: 1등과 2등이 모두 정상적으로 뽑혔을 때만 비교를 진행합니다.
    if len(pair) == 2:
        # [1차-단어분해]: m(1등 DMatch 객체), n(2등 DMatch 객체) = pair(2개 요소 언패킹)
        # [2차-예시/비유]: 1등 후보 m과 2등 후보 n을 나란히 세웁니다.
        m, n = pair
        # [1차-단어분해]: if m.distance(1등 거리) < self.ratio_thresh(0.75) * n.distance(2등 거리의 75%): good_count += 1
        # [2차-예시/비유]: 예를 들어 1등 거리가 30이고 2등 거리가 100이면(30 < 75) 1등이 압도적이므로 합격! 반대로 1등 70, 2등 75면 둘 다 헷갈리는 오매칭이므로 탈락시킵니다.
        if m.distance < self.ratio_thresh * n.distance:
            good_count += 1
```

## 7. Windows 한글·공백 경로 안전 이미지 입출력 (`src/feature_matcher.py`, `src/visualizer.py`)
- **선정 이유**: OpenCV의 C++ 백엔드(`cv2.imread`, `cv2.imwrite`)는 Windows에서 경로에 한글(`안재현`, `스냅샷 저장소`)이 포함되면 조용히 `None`이나 `False`를 반환하며 실패합니다. 한국 실무 환경에서 반드시 알아둬야 할 1순위 방어 패턴입니다.

```python
# [1차-단어분해]: raw(1D 바이트 배열) = np.fromfile(파일을 원시 바이트로 읽는 NumPy 함수)(str(path)(문자열 경로), dtype=np.uint8(부호 없는 8비트 정수))
# [2차-예시/비유]: OpenCV에게 한글 폴더 주소를 직접 주면 길을 잃으므로, 한글을 잘 읽는 파이썬/NumPy가 먼저 파일 알맹이(바이트)를 통째로 꺼내옵니다.
raw = np.fromfile(str(path), dtype=np.uint8)

# [1차-단어분해]: img = cv2.imdecode(메모리 버퍼를 이미지 행렬로 복원)(raw(바이트 배열), cv2.IMREAD_GRAYSCALE(흑백 로드 플래그))
# [2차-예시/비유]: 꺼내온 바이트 덩어리를 메모리에서 바로 흑백 사진으로 펼쳐주면 한글 경로 문제를 100% 우회합니다.
img = cv2.imdecode(raw, cv2.IMREAD_GRAYSCALE)

# [1차-단어분해]: ok(성공 불리언), encoded(압축된 PNG 바이트 배열) = cv2.imencode(이미지를 메모리 버퍼로 인코딩)(".png"(확장자), frame(BGR 프레임))
# [2차-예시/비유]: 저장할 때도 반대로 OpenCV가 메모리 안에서 먼저 PNG 파일로 압축만 해줍니다.
ok, encoded = cv2.imencode(".png", frame)

# [1차-단어분해]: out_path(Path 객체).write_bytes(바이트 직접 쓰기 메서드)(encoded.tobytes()(NumPy 배열을 순수 bytes로 변환))
# [2차-예시/비유]: 압축된 PNG 바이트를 파이썬 Path가 한글 폴더 안에 안전하게 파일로 기록해 줍니다.
out_path.write_bytes(encoded.tobytes())
```

## 8. `try-finally` 리소스 안전 해제 및 키보드 제어 루프 (`src/app.py`)
- **선정 이유**: 웹캠(`VideoCapture`)이나 비디오 파일(`VideoWriter`)을 예외 발생 시 제대로 닫지 않으면 카메라 장치가 잠기거나 MP4 파일 헤더가 손상되어 재생할 수 없게 됩니다. `try-finally`와 `waitKey(1) & 0xFF` 비트 마스크는 실시간 영상 앱의 필수 정석입니다.

```python
# [1차-단어분해]: try:(예외 발생 가능 본문 시작) ... finally:(정상 종료·break·예외 무관하게 100% 실행되는 정리 블록)
# [2차-예시/비유]: 영상 분석 도중에 에러가 나거나 사용자가 강제로 꺼도, 나갈 때 반드시 카메라 전원 스위치와 창문을 닫고 나가게 하는 안전장치입니다.
try:
    # [1차-단어분해]: key(하위 8비트 아스키 코드) = cv2.waitKey(키 입력 대기 함수, ms 단위)(1 if not paused else 30) & 0xFF(상위 플랫폼 비트 마스킹)
    # [2차-예시/비유]: 재생 중엔 1ms만 짧게 기다려 최고 속도를 내고, 일시정지 중엔 30ms씩 쉬어 CPU 과열을 막습니다. '& 0xFF'는 64비트 OS에서 붙는 쓰레기 비트를 잘라내어 순수 키보드 문자만 남깁니다.
    key = cv2.waitKey(1 if not paused else 30) & 0xFF
    # [1차-단어분해]: if key in (ord("q")(문자 'q'의 아스키 코드 113), 27(ESC 키 코드)): break(루프 탈출)
    # [2차-예시/비유]: 사용자가 'q'나 'ESC'를 누르면 즉시 재생을 종료합니다.
    if key in (ord("q"), 27):
        break
    # [1차-단어분해]: if key == ord("p"): paused = not paused(불리언 토글 반전)
    # [2차-예시/비유]: 'p'를 누를 때마다 재생 ↔ 일시정지 스위치를 딸깍 바꿉니다.
    if key == ord("p"):
        paused = not paused
finally:
    # [1차-단어분해]: cap.release()(카메라/파일 핸들 해제); cv2.destroyAllWindows()(OpenCV GUI 창 모두 닫기)
    # [2차-예시/비유]: 극장 상영이 끝나면 영사기(cap) 전원을 끄고 스크린 창을 깔끔하게 닫아 메모리를 돌려줍니다.
    cap.release()
    cv2.destroyAllWindows()
```
